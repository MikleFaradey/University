Клиент-серверное приложение «Игровая статистика пользователей» с Pydantic

1. Цель работы

Разработать клиент-серверное приложение на Python, которое хранит игровую статистику пользователей, обрабатывает HTTP-запросы и выполняет проверку входных данных с помощью библиотеки Pydantic.

2. Реализация

Сервер реализован средствами стандартной библиотеки Python на основе HTTPServer и BaseHTTPRequestHandler. Данные пользователей хранятся непосредственно в коде сервера. В отличие от первого задания каждый пользователь представлен моделью UserStats, наследующей BaseModel из Pydantic.

Модель UserStats содержит поля name, game, level, score и playtime_hours. Для числовых полей level, score и playtime_hours задано ограничение ge=0, поэтому отрицательные значения не проходят валидацию.

Для тела запроса POST /users/<id>/score используется отдельная модель ScoreUpdate. Поле score должно быть целым неотрицательным числом. При нарушении формата сервер перехватывает ValidationError и возвращает клиенту ответ 400 в формате JSON.

3. Реализованные запросы

GET /users — возвращает данные всех пользователей.
GET /users/<id> — возвращает данные конкретного пользователя.
POST /users/<id>/score — прибавляет переданное количество очков к текущему счету пользователя.

4. Обработка ошибок

400 Bad Request — пустое тело, невалидный JSON, неправильный тип или значение score.
404 Not Found — пользователь или маршрут не найден.
405 Method Not Allowed — HTTP-метод не поддерживается для маршрута.
500 Internal Server Error — внутренняя ошибка сервера. Для демонстрации предусмотрен тестовый маршрут GET /error.

5. Проверки устойчивости

Проверены следующие ошибочные ситуации:
1) запрос к несуществующему пользователю;
2) запрос к несуществующему маршруту;
3) POST-запрос без тела;
4) POST-запрос с невалидным JSON;
5) передача строкового значения вместо целого числа в score;
6) использование DELETE для маршрута /users;
7) искусственно вызванная внутренняя ошибка сервера;
8) обрыв TCP-соединения клиентом посреди отправки тела POST-запроса.

После всех ошибочных запросов клиент выполняет контрольный GET /users. Получение ответа 200 OK подтверждает, что сервер продолжает работать и принимает новые запросы после ошибок.

6. Вывод

В ходе работы клиент-серверное приложение из первого задания было дополнено валидацией Pydantic. Проверка данных вынесена в модели, некорректные запросы не приводят к аварийному завершению сервера, а результаты работы и ошибок записываются в server.log, client.log и test_results.txt.
