# Отчёт о выполнении ДЗ № 4

## Исходные данные

В ДЗ № 3 анализировался банковский сервер преподавателя. В отчёте `Python/Homework_3/DZ3_Semgrep_Report.md` зафиксированы шесть срабатываний: использование MD5 и искусственная задержка между чтением и изменением баланса. Дополнительно изучены все 12 attack-скриптов в `dz-3`. Исходный сервер преподавателя: blob `02c2cd7d8572e98e4218ac8a9d63ccf035bab2bd`.

Реализация ДЗ № 4 находится в отдельной папке. Таблица исправлений, протокол и команды запуска приведены в [README.md](README.md). MD5 заменён на scrypt, `time.sleep` из операции перевода устранён. Вместо незащищённого JSON и `fake_sql` используется SQLite с параметризованными запросами, транзакциями и ограничениями данных. Добавлены TLS, разграничение доступа, защита от повторного списания и ограничения ресурсов. Настроено журналирование событий без содержимого команд и секретов.

## Результаты статического анализа

В `semgrep-report.json` перечислены четыре просканированных файла: `bank_client.py`, `Dockerfile`, `main.py` и `setup_demo.py`. Отчёт подтверждает отсутствие срабатываний **в рамках выполненного сканирования**, но не отсутствие всех возможных уязвимостей. Ранее правила Semgrep были скачаны из официального репозитория на commit `17e31e11ebac99fb7dfe1cd288f7a32151b6f3f9`; сохранённый JSON не фиксирует commit набора правил, поэтому для полной воспроизводимости его следует сверить отдельно.

Ранее в Linux повторный запуск Semgrep не удавался из-за ошибки загрузки `libtree-sitter.so.0.26`. Это ограничение устарело: в репозитории теперь сохранён результат успешного сканирования. Результаты тестов, Docker и Semgrep относятся к разным проверкам и не заменяют друг друга.

## Что осталось для оформления сдачи

1. Если нужны скриншоты, приложить запуск Docker, его статус и результат Semgrep на основе сохранённых артефактов. Не представлять сохранённые логи как новый запуск.
2. Для полного подтверждения прав `0600` отдельно выполнить `test_database_file_permissions` на POSIX-системе: в текущем Windows-выводе этот тест пропущен.
3. При требовании воспроизводимого статического анализа указать фактически использованные конфигурации и commit правил Semgrep, а при необходимости сохранить журнал сборки Docker.

Фактический запуск Docker и результат Semgrep теперь документированы. Границы модели угроз (права root, откат БД, распределённый DoS) описаны в README.md.
