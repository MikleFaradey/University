# Отчёт о выполнении ДЗ № 4

## Исходные данные

В ДЗ № 3 анализировался банковский сервер преподавателя. В отчёте `Python/Homework_3/DZ3_Semgrep_Report.md` зафиксированы шесть срабатываний: использование MD5 и искусственная задержка между чтением и изменением баланса. Дополнительно изучены все 12 attack-скриптов в `dz-3`. Исходный сервер преподавателя: blob `02c2cd7d8572e98e4218ac8a9d63ccf035bab2bd`.

Реализация ДЗ № 4 находится в отдельной папке. Таблица исправлений, протокол и команды запуска приведены в README.md. MD5 заменён на scrypt, `time.sleep` из операции перевода устранён. Вместо незащищённого JSON и `fake_sql` используется SQLite с параметризованными запросами, транзакциями и ограничениями данных. Добавлены TLS, разграничение доступа, защита от повторного списания и ограничения ресурсов. Настроено журналирование событий без содержимого команд и секретов.

## Фактически выполненные проверки

Среда: Python 3.12.14, Linux.

| Проверка | Результат |
|---|---|
| `python -m unittest -v test_security` | 14 тестов, OK; полный вывод в test-results.txt |
| 20 конкурентных переводов по 400 из начальных 5000 | Ровно 12 успешных, остаток 200; общий баланс сохранён |
| Replay после повторного открытия БД | Повторного списания нет; конфликт содержимого с прежним ID отклонён |
| Отрицательные/некорректные суммы, self-transfer, IDOR, ADMIN SQL, инъекция в LOGIN | Отклонены |
| Фрагментация TCP, несколько команд в пакете, слишком длинная строка, неверный UTF-8 | Тесты прошли |
| Незавершённая строка Slowloris | Соединение ограничено абсолютным сроком чтения строки |
| Интеграционный запуск сервера и клиента через TLS | Вход, BALANCE, TRANSFER, replay, запрет HISTORY 3 и QUIT проверены |
| Проверка доверия сертификату | Клиент без доверенного сертификата получил SSLCertVerificationError |
| Docker build / запуск контейнера | **Не выполнены:** Docker отсутствует в среде; подготовлены Dockerfile и compose.yaml |
| Повторный Semgrep Python + Dockerfile | **Не выполнен:** установленный исполняемый файл не запускается из-за `libtree-sitter.so.0.26: cannot open shared object file` |

Правила Semgrep скачаны из официального репозитория, commit `17e31e11ebac99fb7dfe1cd288f7a32151b6f3f9`. Запуск с двумя конфигурациями (`python` и `dockerfile`) завершился до сканирования. Поэтому новый JSON-отчёт и число срабатываний не приводятся; утверждения о «0 уязвимостей» нет. Установка другой версии также не дала рабочего запуска в этой среде.

## Что нужно завершить перед сдачей

1. Запустить `docker compose up --build -d` по README, проверить `docker compose ps`, команды клиента и логи.
2. Выполнить команду Semgrep из README в локальной среде, сохранить реальный `semgrep-report.json`.
3. Разобрать фактические срабатывания, приложить вывод/скриншоты запуска Docker и Semgrep. Для добавления JSON в git используйте `git add -f Python/Homework_4/semgrep-report.json` из корня репозитория.

Код и тесты подготовлены, но два пункта задания — фактический Docker-запуск и повторный статический анализ — требуют этих действий. Ограничения модели угроз (права root, откат БД, распределённый DoS) явно указаны в README.
