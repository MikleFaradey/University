## Исправления

| Проблема / атака из ДЗ № 3 | Изменение |
|---|---|
| MD5 и известные пароли | scrypt (`n=32768, r=8, p=1`), отдельная случайная соль; случайные пароли создаёт `setup_demo.py` |
| SQLi в LOGIN | Параметризованные запросы SQLite, строгий формат логина; `fake_sql` удалён |
| ADMIN SQL / утечка хешей | Разрешена только команда `ADMIN USERS`, только администратору; хеши и соли не выдаются |
| IDOR | HISTORY доступна только для собственного ID |
| Отрицательные суммы, NaN, бесконечность, дробные копейки | Строгая проверка формата; хранение в целых копейках; ограничения в БД |
| Self-transfer | Перевод самому себе запрещён |
| Race condition | Проверка, списание, зачисление и запись операции внутри `BEGIN IMMEDIATE`; ошибка откатывает транзакцию |
| Replay | Обязательный ID запроса; UNIQUE(from_id, request_id); повтор возвращает прежний номер операции без списания, в том числе после перезапуска |
| Перехват паролей и команд | Обязательный TLS; клиент проверяет сертификат и имя сервера |
| Brute force | Не более 5 попыток входа на аккаунт в минуту, включая успешные; максимум 2 одновременных scrypt |
| DoS / Slowloris | Максимум 32 соединения, 5 секунд на TLS, 60 секунд на целую строку, 2048 байт на строку, 200 команд / 300 секунд на соединение |
| Фаззинг / TCP-фрагментация | Строгий UTF-8, накопление строки до LF, обработка нескольких строк одного пакета, ограниченные ответы |
| Подмена bank_db.json | JSON больше не импортируется; SQLite в отдельном томе, файл 0600; непривилегированный контейнер |
| Утечки через логи | Логи содержат результат запроса, ID пользователя и транзакции, но не пароль, тело команды, соль или хеш |

## Запуск локально

После каждого ответа сервера на ввод полной следующей команды (до перевода строки) отводится 60 секунд. Это удобнее для демонстрации, но по сравнению с 10 секундами одно неактивное соединение может дольше занимать слот. Сохраняются пределы 32 одновременных соединений, 200 команд и 300 секунд общего времени сессии (проверяется между командами).

```bash
cd Python/Homework_4
python3 setup_demo.py
python3 main.py
```

Нужен OpenSSL с поддержкой `req -addext` и `-noenc` (OpenSSL 3). Пароли находятся только в локальном `secrets/users.json`. Сертификат самоподписанный и предназначен для лабораторной работы; срок действия 30 дней. Скрипт намеренно не перезаписывает существующие секреты. Во втором терминале из этой же папки:

```bash
python3 bank_client.py
```

Пример команд после входа под alice:

```text
BALANCE
TRANSFER 3 100.50 request_0000000001 test
TRANSFER 3 100.50 request_0000000001 test
HISTORY
HISTORY 3
QUIT
```

Первый перевод списывает 100.50; повтор с тем же ID не списывает деньги. Для новой операции используйте новый ID (16–64 латинских букв, цифр, `_` или `-`; предпочтительно `secrets.token_hex(16)`). Старый формат TRANSFER без ID намеренно отклоняется. Суммы в HISTORY и ADMIN USERS представлены в копейках; BALANCE — в денежных единицах. HISTORY показывает последние 100 операций.

## Docker

Из папки `Python/Homework_4`, после `python3 setup_demo.py`:

```bash
# Разрешить группе контейнера чтение секретов, сохранив владельца на хосте.
sudo chgrp -R 10001 secrets
chmod 750 secrets
chmod 640 secrets/users.json secrets/server.key secrets/server.crt
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 bank
python3 bank_client.py
docker compose down
```

Контейнер работает с UID/GID 10001, доступен только через `127.0.0.1:9999` хоста, имеет read-only корневую ФС, отдельный том БД, ограничения памяти/CPU/PID, удалённые capabilities и ротацию логов. Секреты монтируются только для чтения и исключены из образа. Если Docker Desktop не сохраняет POSIX-права bind mount, проверьте чтение файлов UID 10001; не открывайте приватный ключ всем пользователям. Не запускайте локальный сервер и контейнер одновременно на одном порту.

`docker compose down` сохраняет БД. Не удаляйте том для обычного перезапуска. Пароли из JSON используются только при первом создании БД; изменение JSON не меняет существующие пароли. Учебный `bank_db.json` намеренно не мигрируется. Healthcheck проверяет доступность TCP-порта; полную работоспособность проверяет клиент.


Проверяется исходный **Dockerfile**, а не содержимое собранного образа. Для воспроизводимости сохраните версии Semgrep и commit правил (`git -C semgrep-rules rev-parse HEAD`). Не запускайте исходный `attack_dos.py` с 50 миллионами соединений; локальные тесты воспроизводят ошибки ограниченным числом запросов. Старые attack-скрипты используют открытый TCP и прежние пароли, поэтому их отказ сам по себе не доказывает исправление: тесты проверяют бизнес-логику с корректной аутентификацией.

## Границы защиты

Это учебная работа, не промышленная банковская система. SQLite-транзакции защищают целостность при конкурентных переводах. Права файла и изоляция контейнера ограничивают доступ к БД, но **не защищают от root хоста или злоумышленника с правами пользователя приложения**: такой субъект может изменить SQLite. Криптографической защиты от отката всей БД здесь нет. Ограничения снижают риск истощения ресурсов, но не исключают распределённый DoS; лимит входа в память сбрасывается после перезапуска, а блокировка аккаунта может использоваться для отказа в обслуживании. Идентификатор операции защищает от повтора того же запроса; имеющий действующие учётные данные может создать новую операцию с новым ID. Для реального развёртывания нужны внешний rate limiter, управление ключами, ротация паролей, резервные копии и аудит.
